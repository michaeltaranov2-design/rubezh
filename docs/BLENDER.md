# Blender: построение и проверка оружейных ассетов

## Текущее состояние

Обновлённый генератор работает с Blender 5.2.x; в этой среде установлен и фактически проверен **Blender 5.2.2 LTS**. Основные команды для генерации — `tools/run_weapons.py` (проверка версии/API, пилот, полный набор и независимая GLB-проверка) и `tools/blender/generate_weapons.py`. Чистая геометрическая модель без зависимости от `bpy` находится в `tools/weapon_geometry.py`.

Финальный проверенный набор этого выполнения: `generated/refresh-iter5/`. Старые результаты итераций сохранены; запускатель отказывается перезаписывать непустой путь, поэтому следующую генерацию направляйте в новое имя каталога.

```powershell
python -m unittest discover -s tests -v
python tools/run_weapons.py --blender 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --out generated\my-run --allow-newer --full
```

`--allow-newer` — явное разрешение использовать установленную версию относительно каталожного gate. Для конкретной машины подтверждена совместимость 5.2.2 LTS. Генератор запускает сначала пилот; полный набор выполняется только после успешной проверки пилота. Отдельно сохраняются `session-report.json`, логи пилота/полного прохода и `full/manifest.json`.

Последнее измеренное состояние: 49 Python-тестов `OK`; API-проба Blender прошла; экспорт и независимая проверка завершились `exportsValidated`; создано 13 `.blend`, 13 атласов и 39 GLB. Не считайте старые каталоги частичных попыток финальными и не удаляйте их автоматически.

## Структура экспорта и бюджеты

Для каждой модели в `full/<id>/`: `<id>.blend` (LOD0), `<id>_atlas.png` (PNG 1024×1024), `<id>_LOD0.glb`, `<id>_LOD1.glb`, `<id>_LOD2.glb`. Текстура упакована внутрь каждого GLB. Каждый LOD автономен и имеет sockets/AnimationPlayer clips; LOD1/2 не предполагается отображать одновременно с LOD0.

Финальные бюджеты проверяются именно в треугольниках: пистолеты/нож LOD0 1 500–2 500; SMG/винтовки/дробовик 3 000–5 000; снайперка 4 000–6 000; гранаты 800–1 500; LOD1 300–1 200; LOD2 1–300. Измеренные значения каждой модели записаны в `full/manifest.json`; `sniper_horda` LOD1 = 1 192 и близка к верхнему пределу.

У LOD0 геометрия разбита на семантические отдельные mesh-объекты (receiver, barrel, muzzle_brake, handguard/stock, grip, magazine, optic_mount/optic_sight и органы управления; точный список каждой модели — в manifest). Для анимаций отдельны slide, magazine, trigger/safety, pump/magazine_tube, pull_ring/retaining_pin и другие указанные там подвижные компоненты. Нож — blade/handle/guard/pommel. Реальные стабильные имена — Pascal/snake case из manifest, не два старых монолитных объекта body/moving_part.

## Атлас, AO и палитры

Генератор создаёт один квадратный 1024×1024 PNG на модель с градиентными полями/графическими мотивами и тремя цветовыми рядами. AO запекается Blender в vertex color `AO_Baked`, экспортируется как glTF `COLOR_0`, затем контраст ремапится `0.38 + 0.62 * rawAO`. В GLB используется лёгкий материал с упакованным PNG; дополнительных игровых шейдеров не требуется.

В `skins.json` описаны строки и V-смещения: `graphite_outline` («Графитовый контур», шестиугольная насечка), `polar_pulse` («Полярный импульс», диагональный шеврон), `dust_code` («Пыльный код», ломаная сервисная линия). По умолчанию экспортирован материал первого скина. Переключение UV-строки возможно из игрового материала, но runtime-переключение палитры ещё не подключено/не проверено, поскольку игровой проект отсутствует. Атлас создаётся скриптом, это не ручная покраска художником.

## Имя, оси и sockets

Исходные ID ассетов не менялись. Для каждой модели экспортируются ровно четыре прежних socket ID: `socket_muzzle`, `socket_eject`, `socket_hand_r`, `socket_hand_l`. Объект прицела — отдельные `optic_sight`/`optic_mount`; `socket_sight` намеренно не создавался и `socket_hand_l` не заменяет его.

Локальные координаты Blender: +Y вперёд, +Z вверх, метры; glTF в Godot применяет смену осей. По фактическому импорту Godot 4.7.2 сохранены прежние направления: у огнестрельного оружия и ножа muzzle — локальная -Z, у гранат — локальная +Y; eject — +X, обе точки рук — -Z. Направления и IDs проверены во всех 39 GLB. Окончательную привязку рук/IK к скелету игры всё равно требуется сверить в самой игровой сцене.

## Визуальный review и Godot

Рендер-скрипт всех LOD0 Blend:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --python tools\blender\render_review.py -- --blend-dir generated\refresh-iter5\full --out generated\refresh-iter5\review\iteration-5
python tools\make_preview_sheet.py generated\refresh-iter5\review\iteration-5 --title 'Рубеж — итоговая итерация'
```

Каждая модель рендерится с четырёх камер (front, side, top, three-quarter), 512×512, нейтральный фон, EEVEE и мягкий свет. Общий лист `review/iteration-5/preview-sheet.png`, offline gallery `review/iteration-5/gallery.html`. Проход включал пять итераций: по отзывам исправлялись слишком тёмный AO, зазоры stock/receiver и bullpup handguard, положение магазинов и поддержка оптики; затем доводились мушка дробовика и посадка навершия ножа. Финальный LOD0 набор повторно отрендерен после правок.

Финальный импорт Godot 4.7.2 проверен headless в `generated/refresh-iter5/godot-validation-project/`: импорт 39/39 GLB; сцены содержат mesh surfaces и текстурированные материалы; имена/направления четырёх sockets совпали с контрактом; присутствуют клипы `idle`, `fire`, `reload`, `inspect` с ненулевой длительностью и дорожками. Это проверка импортированных ресурсов/структуры, не проигрывание анимаций в полноценной боевой сцене.

Игрового Godot-проекта или целевого исполняемого файла в репозитории нет. Поэтому сборка игры, фактическая постановка модели в руки игрока, runtime-переключение скинов, дистанции переключения LOD, воспроизведение в кадре, draw calls, FPS и профилирование целевой игры **не проверялись**. Не выдавайте тест отдельной GLB-сцены за профилирование игры.
