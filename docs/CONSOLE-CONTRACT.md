# Оригинальная консоль нашей игры
Это проект, не реализация CS2 и не вмешательство в чужие игры. Параметры, значения и ограничения придуманы для Рубежа; соответствие CS2 не обещается.

## Грамматика
- game give <игрок|self|all> <модуль> [ключ=значение ...] — Серверная активация с расходованием квоты
- game revoke <игрок|self|all> <модуль> — Отзыв без возврата квоты
- game set <модуль> <параметр> <значение> — Изменить профиль для следующей активации, не текущий эффект
- game list — Список модулей и доступности
- game status <игрок|self> — Оставшиеся активации и сроки эффектов
- help [команда] — Справка из каталога
- noob on|off — Подсказки следующего токена и понятные ошибки
Имена игроков с пробелами заключаются в двойные кавычки; поддерживаются экранированная кавычка и обратная косая черта. Сервер разрешает игрока в стабильный accountId; неоднозначный ник отклоняется. self означает инициатора, all — снимок допустимых получателей. Повторный ключ, неизвестный параметр, NaN/Infinity, некорректный bool, лишние токены и значения вне диапазона отклоняются. Числа используют точку.

## Лимиты и права
Три успешные активации КАЖДОГО канонического модуля на accountId за матч. Это допущение вместо буквального ограничения справки. Все алиасы используют один счётчик. Квота инициатора и каждого получателя проверяется до атомарного применения; self не списывает дважды. all списывает одну попытку инициатора и по одной получателю; частичная выдача запрещена. Для серверного модуля списывается только квота администратора-инициатора, all обозначает серверную область, а не N применений. Самостоятельная выдача — только себе; чужой игрок и all требуют modifier.others. Серверная экономика требует server.economy. Полномочия выдаёт сервер, не профиль клиента. sv_cheats переключает только администратор вне этого интерфейса.

Эффект включён в раунде r до окончания r+1 либо окончания матча. Смерть, выход, смена сторон и reconnect не сбрасывают квоту и не продлевают срок. Новый give тратит попытку и заменяет окончание, не суммируя срок. set меняет только будущий профиль. revoke не возвращает попытку, доступен для своих эффектов без квоты. help/list/status/noob также без квоты, но с rate limit. В 16-м раунде эффект короче двух раундов: матч имеет приоритет.

Все действия сериализуются сервером; nonce обеспечивает идемпотентность повтора, новый nonce не обходит квоту. Неуспешная проверка не списывает попытку. Журнал хранит matchId/accountId, цель, модуль, нормализованные параметры, tick, решение, причину отказа, квоту до/после, срок. Не логировать токены авторизации. Счётчики восстанавливаются после рестарта либо матч явно аннулируется. Активные модули видны в таблице очков.

## Безопасность Competitive
В Competitive wallhack, rage, noclip, rethrow и серверные изменения денег не доступны. Остальные проверяются allowlist сервера. Клиент не получает скрытых врагов; помощь прицеливания/triggerbot принудительно требуют visibleOnly=true, запрос false отклоняется, а не молча исправляется. Сервер использует ту же политику видимости для отправки данных и выбора целей, исключая скрытое наведение как побочный канал. Политика должна учитывать дым и запрет прострелов по неотправленным целям, если требование отсутствия информации трактуется строго.

## Мгновенные действия
rethrow — однократное действие: один запрос, один бросок, одна попытка. Поле durationRounds=null — явное исключение: мгновенное действие нельзя растянуть на два раунда. Повторяется только собственная серверно сохранённая граната. Урон не откатывается. Оружие/гранаты выдаются с leaseId и expiryRound; передача не меняет срок. Граната исчезает из инвентаря при истечении, уже произведённый взрыв не отменяется. health — отдельный бонусный слой; сначала расходуется бонус, остаток снимается при истечении. damage — множитель только пока действует lease. Деньги — временный слой настроек, покупки не откатываются. startmoney влияет на следующую предусмотренную правилами инициализацию, не печатает деньги немедленно; maxmoney >= startmoney проверяется при активации и снятии слоя.

## Совместимые по названию алиасы
sv_showimpacts 1 → game give self impacts mode=both; 2 → client; 3 → server; 0 → game revoke self impacts.
sv_rethrow_last_grenade → game give self rethrow.
mp_maxmoney N → game give all maxmoney amount=N.
mp_startmoney N → game give all startmoney amount=N.
Это только маршрутизация в наш серверный обработчик, а не выполнение системных команд. wallhack/aimbot/skinchanger/rage — собственные механики, не заявленные официальные команды CS2.

## Автогенерация UI
Парсер и UI должны читать один каталог. Tab предлагает допустимые токены по состоянию грамматики, параметрам, типам, правам и режиму. noob показывает ожидаемый токен, описание и пример. Ошибка для «game set aimbot fov»: «Не хватает значения fov, пример: game set aimbot fov 5». Клиентская валидация не заменяет серверную. Текущий пакет содержит данные, а не готовый парсер/автодополнение.

## Сетевые пределы — проектные
Консоль: до 1024 байт UTF-8, 32 токенов, 16 параметров; модификации — token bucket 2 запроса/сек с burst 4; справка/статус — 5/сек с burst 10. Ограничения на accountId и соединение плюс общий лимит сервера; текстовые запросы не допускаются в системный shell/eval. Сервер отвечает ошибкой без выполнения и логирует с агрегированием флуд-отказов.

## Уточнения ревью: обязательные ограничения
Разделы ниже уточняют исходный контракт, не добавляя клиентских полномочий. Собственный revoke разрешён только аутентифицированному владельцу получателя; отзыв чужого эффекта требует modifier.others. Серверные эффекты всегда требуют server.economy и цель all. Проверка полномочий предшествует разрешению цели, квоте и изменениям. set никогда не изменяет активный эффект. Поля прав, accountId и режим берутся из серверной сессии, не из тела RPC.

impacts оставляет оба источника точек, но сервер выдаёт только собственные выстрелы получателя и разрешённую видимую статическую геометрию в Competitive. Точка, нормаль, урон, звук, entityId и время скрытого динамического попадания не передаются. Клиентские точки — только визуальный прогноз, не доказательство попадания. Один фильтр видимости действует для снимков, событий, консоли, помощи прицеливания и зрителей.

Идемпотентность: ключ (matchId, accountId из сессии, requestId 128 бит) связан с хешем нормализованного запроса. Другое тело с тем же ID отклоняется. Один журнал мутаций и изменение состояния фиксируются атомарно в последовательном исполнителе матча. Повтор возвращает прежнее решение и не исполняется вновь. В памяти не более 64 ответов на игрока; после вытеснения читается долговечный журнал. Записи не удаляются до закрытия и архивирования матча. На игрока не более 2048 новых ID мутаций за матч, затем новые запросы отклоняются до обработки, повторы продолжают обслуживаться. Токен-бакет действует и на повторы; восстановление с неоднозначным commit прекращает приём команд до reconcile.

Очереди ограничены 8 запросами на аккаунт и 256 на матч. Переполнение отклоняет запрос без списания квоты. Запрет unbounded очередей, таймеров и логов. Отказы флуда агрегируются, но итог каждой принятой мутации сохраняется. В журнал нельзя писать пароли, сессионные токены и произвольные неэкранированные строки.

status чужого игрока показывает только публичные активные модули и срок. Параметры, остатки квот и история доступны самому игроку либо modifier.audit. Объекты скрытых противников и их координаты не возвращаются даже через диагностические ошибки.

Экономика: одно активное значение каждого серверного модуля; новая разрешённая активация заменяет старое, но не возвращает квоту. При истечении сначала атомарно снимаются ВСЕ истёкшие слои, затем эффективные стартовые деньги ограничиваются итоговым потолком. Активация пары start > max отклоняется. Истечение никогда не отклоняется и не продлевает привилегию ради проверки инварианта. Изменения не отбирают уже купленные предметы.
